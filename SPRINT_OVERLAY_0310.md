# Sprint displacement overlay — 0.3.10

This optional developer experiment tests whether code displacement can coexist with native sprint without the engine pulling the Griffin back. It does not enable the dive/climb speed model or alter normal flight unless started manually.

End driving and Reset scripts; confirm v0.3.10. Sprint steadily for about two seconds, then press **冲刺位移叠加对照（+6米／秒，自动结束）** in DEBUG. Keep steady flight for the full ten-second sequence: two seconds original speed, six seconds with +6 m/s code displacement, two seconds after addition stops. Record A/B/recovery, write count, immediate Transform/controller errors, and whether flight visibly accelerates, pulls back or jitters. About 24 → 30 → 24 m/s would support effective addition; coordinate readback alone is not visual acceptance.

The post-UpdateBehavior callback reads the current Griffin Universal position, adds one elapsed-time-scaled step along the normalized measured world flight direction, then writes Transform, PosRotContext and character-controller warp using the existing scoped hover synchronization APIs. It preserves current rotation, native sprint/action, navigation and actual current position on exit. No captured absolute flight path is reapplied. Measured speed determines direction only; it never feeds back into the fixed +6 magnitude.

The test measures actual position deltas at successive post-behavior sampling points. It excludes settling intervals and reads Transform and controller coordinates back immediately after each write. Next-frame reverse displacement is a diagnostic clue, not proof of rollback: native movement can conceal cancellation without going backward. Effective boost is judged from the measured A/B/recovery speed response, separately from visual stability. An ineffective engine overwrite is rejected in offline tests.

Default-off, session-only, no settings or file writes, no shared/native speed parameter changes. Timing and overlay tests cannot run together. Only the retained spawned Griffin and captured physics components are written. Ground/non-sprint action, pause, gear/owner/external changes, stale direction samples and gaps over 0.1s cancel. Partial setter failure retains a current-position repair record, retried by lifecycle/reset when references survive; never restore an old entry coordinate. LT continues to inherit measured total world velocity, including the addition, then the overlay cancels in gear 1.

All 26 Lua54 modules compile and prior regressions pass, with/without optional Debug. New mock tests cover native24/boost30/recovery24, simulated native pullback rejection, 30/120Hz integration, current-position-only writes, fixed magnitude and duplicate-clock exclusion, Transform/context/controller synchronization, unchanged rotation, pause/ground/action/phase/ownership/external/gap cancellation and partial failure/reload repair. Actual callback integration verifies measured speed and LT inheritance of 30 m/s. Native coexistence and visual flight remain unverified until game testing.
