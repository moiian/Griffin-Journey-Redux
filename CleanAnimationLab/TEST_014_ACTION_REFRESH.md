# 0.1.4 悬停刷新实验

目标是复现隔离中请求新动作、短暂放行原生执行、随后重新隔离的顺序。同步重置后立即冻结不再作为本版修复路径。默认关闭，需状态记录；本轮只改变进入隔离的流程，原生效果待验收。

## 离线检查

- 七个Lua文件通过Lua54语法检查；已有隔离生命周期、恢复重试、状态记录及方法前后配对回归通过。
- 模拟确认请求发生于FSM=false／RootMotion=None之后，短暂放行恢复初始控制值，实际行为更新前不能重新冻结。
- 动作名已变但基础层仍为隔离资源时继续等待；延迟原生执行时不重复请求；确认后播放最新选择，保留隔离轮及初始控制值。切片、隔离内修改选项不重发。
- 暂停及已排队暂停、过期版本、取消、Reset、精确实例／组件／驾驶归属变化、关闭记录、原false FSM、请求异常、超时及无自动重试均通过；飞控只拦截已重新隔离的精确对象，放行阶段及无关对象保留原调用。
- 请求、放行、确认、重新隔离分别留快照；轮询不逐帧新增事件，状态样本与原有记录上限保持。

## 实机验收

按README的六步执行：新实例，绑定及记录，勾选悬停刷新，首次隔离一次。核对1次请求／1次返回／1次确认；分别观察刷新过程位移和确认后5100是否持续移动，稳定则保持隔离切5101。失败直接保存，不等待落地、不反复开关。

三个计数代表请求和确认阶段，不代表旧行为已被彻底取消或画面静止。若出现超时，保留日志判断实际动作及基础层，不扩大为盲目连续请求或额外AI清理。
